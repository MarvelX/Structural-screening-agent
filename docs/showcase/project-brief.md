# Project Brief

## 项目一句话

**BV PV Design Review Workbench / BV 光伏结构设计审核工作台** 是一个面向**第三方审核工程师**的审核支持产品，用于组织光伏结构设计审核范围、审核依据、资料完整性、风险登记、ITP / review plan 与报告编制，并在正式签审前输出可追溯的工程判断。

## 这个项目想解决什么问题

在第三方审核场景下，团队首先要回答的往往不是“如何完成正式设计”，而是“当前审核范围是否清楚、依据是否完整、风险是否被识别、资料是否足够支撑下一步判断”。

传统上，这类判断依赖资深审核工程师快速结合图纸、证据、经验和规范路径，完成前期审核组织与技术复核：

- 当前审核范围和分工是否清楚
- 审核依据与 document completeness 是否满足启动条件
- 哪些风险需要进入 risk register 跟踪
- ITP / review plan 应如何编排
- 报告结论应如何组织，哪些部位控制是否值得进入下一轮正式复核

这个项目的目标，就是把这类第三方审核支持工作数字化，同时保留可解释、可追溯的工程判断链。

## 核心能力

- 支持定义 review scope，并把审核 basis、资料完整性检查项和风险登记组织到同一工作台
- 支持维护 ITP / review plan，明确审核输入、检查动作与输出交付
- 支持报告编制与组合，输出结构初筛复核摘要，支持 Markdown / Word / PDF 导出
- 在具体场景模块中识别当前控制因素：檩条、主门架梁、主门架柱或连接路径
- 在资料缺失时使用保守假设，而不是直接失效
- 通过 basis 与 traceability 说明“为什么是这个结论”

## 首个场景模块

现有的 screening kernel 继续作为产品内模块保留，并作为第一个场景模块落地：**门式刚架屋面光伏增载场景模块**。

这个模块承接既有厂房或仓库屋面加装光伏的快速复核需求，用于在资料不完整、决策前置的阶段输出可追溯的 screening-level 判断。

## 为什么它不是一个通用 AI demo

- 它不是聊天问答驱动的界面
- 它不是简单的 if-else 表单分流
- 它不是直接让大模型生成结论
- 它的底层是**确定性 screening kernel + 规范路径 + 工程假设 + 导出交付**

真正有价值的地方，不是“能不能说得像结构师”，而是“能不能像结构师那样留下控制路径、假设边界和依据链”。

## 当前边界

- 当前产品定位是第三方审核支持，而不是正式设计签署、法定审图或出具设计签章结论
- 当前首个内嵌模块聚焦于门式刚架 + 屋面光伏增载场景
- 当前属于 screening-level 结构复核
- 支持 `GB / AISC / Eurocode` 的规范路径选择
- 不替代正式计算书、有限元分析、签章审查或施工图设计

## 为什么这个项目有代表性

这个项目的代表性，不只在于做了一个结构专业 demo，而在于它体现了从问题定义到产品化落地的一整条链路：

- 把真实第三方审核场景收敛成明确产品边界
- 用领域模型和 screening kernel 承载工程判断，并将其保留为首个场景模块
- 用 basis / traceability 把结论做成可解释系统
- 用 UI 和导出把结果组织成决策者可消费的形式

因此，这个项目既能体现结构工程判断能力，也能体现工程工具产品化和技术负责人的收口能力。
